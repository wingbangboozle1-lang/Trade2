Live Kalshi demo tracker

A continuously refreshed view of the highest-dollar live events on the Kalshi demo exchange, limited to five topics — gas prices, elections, culture, crypto and golf — with a real-time alerting system for contract price swings of $0.10 or more, liquidity depth, an explainable ROI model and a fully automated simulated-trading engine.

Executive summary

  • Scope. Only Kalshi demo markets whose series matches the five tracked topics are collected. The Kalshi API's own category filter on GET /events is ignored by the service, so topics are derived locally from series and market titles, and Kalshi's category strings are stored unedited.
  • Refresh cycle. A GitHub Actions workflow runs the collector every 10 minutes against external-api.demo.kalshi.co/trade-api/v2 and commits the snapshot. No manual step, no credentials, no server.
  • Alerts. A swing is a move of at least $0.10 in either direction, measured two ways: between consecutive trade prints from the Kalshi trade feed, and against the previous_price_dollars Kalshi reports for the market. Both feeds land in the two scrolling chats on the dashboard.
  • ROI model. Every market is scored 0–100 from five published components — momentum, liquidity, spread, edge and time-to-close. The right-hand chat filters on that score, and the model prints the reasons behind every score so it can be audited.
  • Liquidity. The dashboard shows the YES and NO bid ladders with the number of contracts resting at each price, because Kalshi publishes bids only: a YES bid at $0.07 is the same level as a NO ask at $0.93.
  • Trading. Three strategies (swing momentum, mean reversion, liquidity capture) are backtested on hourly candles and then traded forward on every cycle. Positions are marked to the live bid and settle at $1/$0 when Kalshi reports a resolution of yes or no. Every trade on the site is simulated.
  • Honesty guard-rails. The site never presents a simulated trade as a real fill, and any value that could not be confirmed against an official Kalshi source is left blank and published on the Flagged for review page.

How the data flows

1 · Collect

Node collector in pipeline/src/collect.js reads the public Kalshi demo REST API: series discovery, market snapshots, orderbooks, candles and the trade feed.

2 · Detect

Swings of $0.10 or more are extracted from consecutive fills and from Kalshi's previous price; each alert keeps its ticker, prices, timestamp and source links.

3 · Simulate

The paper engine backtests three strategies on hourly candles, then trades forward on the live book, tracking positions until the market resolves.

4 · Publish

JSON snapshots are committed to docs/data/ by a scheduled GitHub Actions run; GitHub Pages serves this site straight from the repository.

Suggestions to make this more live and interactive

  • Server-Sent Events instead of polling. A small always-on collector with an SSE endpoint would push every fill to the browser the moment it prints, turning the 10-minute snapshot into a true tick feed. The WebSocket API already supports this (ticker and trade channels) but requires an API key.
  • WebSocket upgrade. Connect the browser to wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2 for ticker, trade and market_lifecycle channels, so price changes render without waiting for the next snapshot. It needs a signed handshake, so it has to run behind a thin proxy that holds the key.
  • Push the swing alerts out of the browser. Add Kalshi price alerts (POST /price_alerts via the MCP connector) or a Telegram/Discord/Slack webhook so a $0.10 move reaches the trader even when the tab is closed.
  • One-click order tickets. Render a signed order ticket per market from the V2 shape (POST /portfolio/events/orders) so a trader can review and submit on Kalshi without leaving the page.
  • Depth-of-book heat map. The liquidity panel currently shows a ladder; a two-sided heat map over time would reveal liquidity being pulled ahead of a move.
  • News-correlation overlay. Annotate swing markers with the settlement sources Kalshi publishes for the market and fetch those pages' timestamps, so a jump can be lined up with the article that caused it.
  • Alert persistence and filters. Store alert thresholds per topic, mute tickers, and add a "repeat only if it breaks a new high/low" rule to keep the chat readable on busy books.
  • Paper → real promotion. Once a demo API key exists, let the same strategy engine run against live fills with a hard cap on contracts per market, and diff the simulated and real books.
