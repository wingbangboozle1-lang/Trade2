FL-01 open No Kalshi API credentials exist in this environment and the user directed that there be no manual input. Therefore no real demo-account orders can be placed; the trading module is a simulated paper account that fills against the real demo order book. The portfolio page shows the simulated account, not an exchange-side balance. Project constraint · API keys docs ↗
FL-02 open WebSocket requires an authenticated handshake (KALSHI-ACCESS-* headers signed with an API key), so the site's live layer polls REST (order book / candlesticks / markets) instead of opening wss://external-api-ws.demo.kalshi.co. “Live” = collector cadence (~15 min) plus 20s front-end polling of published JSON, not tick-by-tick WS push. WS quick start ↗ · connection docs ↗
FL-03 open Google News RSS headline lookup cannot be validated from the dev sandbox (egress blocked), so swing-catalyst links are only populated when the GitHub Actions runner fetches them. If a swing has no headline inside ±6h, the link cell stays blank and shows “no verified headline”. Headline ≈ time proximity only — never claimed as the cause of a move. collector/news.py · RSS endpoint ↗
FL-04 open Series limit parameter is ignored by the API: /series?limit=1 returns the full unpaginated list (observed 2026-11-20, responses up to 115 chunks). The collector therefore filters client-side and caps results; row counts can exceed requested limits. reproduce: /series/?limit=1 ↗ · docs ↗
FL-05 open Fee-schedule prose vs table rounding nuance: the PDF says “round up such that fee + positionCost is rounded to a centicent”, while its published General Trading Fees Table matches ceil-to-the-cent of the raw formula on all 42 rows. The engine implements the table reading (test reproduces every row). Difference is ≤ $0.01/contract; flagged for a human to confirm which reading the exchange actually charges. official fee PDF ↗ · trading/test_engine.py
FL-06 open Topic ≠ category: Kalshi categories (Crypto, Culture, Elections, Sports, …) are not the five requested topics. “Golf” is a tag (category=Golf returns null), “gas prices” sits inside Economics/Commodities. Mapping uses official categories/tags/ title rules (see collector/topics.py) and each mapped series row links the exact API URL used, but a human should spot-check borderline series (e.g. broad “Mentions” folded into Culture). category semantics ↗ · docs/data/series.json
FL-07 open Order-book “liquidity” shown is bid-side resting size only (YES bids + NO bids). The API returns no ask arrays — asks are implied at 1 − best opposite bid. Contracts “available at a price” on the ask side are therefore derived, and the chart labels them as bids. orderbook_responses ↗
FL-08 open Thin markets produce empty trade/candle responses (e.g. /markets/trades → {"trades":[]}, candlesticks → empty array). The UI shows blanks with an “unverified” badge rather than substituting values; alerts are simply absent for that window (a missing series is not evidence of no move). candles docs ↗ · trades docs ↗
FL-09 open Branch-name protocol exception: the parallel-session protocol asks for session-<id>/<task> branches, but this Arena session is pinned to arena/c0205283-trade2 by the platform. All work happens on that single branch and the exception is logged in COORDINATION.md. COORDINATION.md
FL-10 fixed in code — applies at next scheduled run Resolutions covered one topic and no “yes” outcomes (session arena-3dcf3f13, X1). The published snapshot had 300 rows: all crypto (DOGE), all no, last ~3 hours. Golf, culture, elections and gas had none. Causes: the same first series per topic every run, a global newest-300 cut that let crypto fill the file, and no accumulation across runs. The fix rotates series per topic, scans the last 30 days (documented min_settled_ts), keeps 60 newest per topic and merges prior rows. The published file changes only when the scheduled collector runs after this merge.
