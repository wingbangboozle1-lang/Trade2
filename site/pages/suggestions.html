Suggestions: make the site more live and easier to trade from

Ideas ranked by value for a trader. Each one cites the official Kalshi source that makes it possible, or says plainly that it is an idea with no verified source. None of these is built yet unless noted.

#SuggestionWhy it helpsFeasibility / source
1Stream prices over WebSocket from a small always-on service. Keep the API key on the server and push ticks to the browser.Gives true second-level charts and immediate ≥ 10¢ alerts instead of 15-minute snapshots.The WebSocket needs an API key [S8]. Demo and production WS hosts are listed in [S3]. Not built (F-09).
2Live order-book ladders from the order-book delta channel.Shows liquidity change as it happens, not only at snapshot time.The WebSocket docs list an orderbook_delta channel in their subscribe example [S8]. Not built.
3Fill and order updates for the demo account from the user WebSocket hosts.Portfolio P&L updates when fills happen, without polling balance.Dedicated user hosts for fill and user_orders are listed in [S3]. Needs the demo key (F-08).
4Show the exact taker fee next to each price, using the official formula, so the net edge of a trade is visible before it is taken.Fees are material at mid prices (up to 1.75¢ per contract at 50¢ on standard series).Formula and table: [S2], implemented in scripts/fees.mjs and tested. Not yet shown in the UI.
5Replace the placeholder High-ROI rule with your model's output.The High-ROI chat then reflects your edge, not a generic filter.Edit high_roi_rule in config/topics.json or feed model scores in (F-13).
6Add a cause-review queue. For each ≥ 10¢ alert, a reviewer adds a news or website link and a confidence note.Answers "what caused this jump?" without guessing automatically.No API field gives the cause (F-10). Manual process; not built.
7Plain-language cards per market: the event title, the one-line resolution rule, closing time, and the current YES/NO price, with the rules a click away.Simplifies decisions, reduces misreads of YES and NO.Rules text is in the market object (rules_primary) [S9]. Partly built (rules links on alerts).
8Respect rate limits when adding feeds. Add tiered polling: fast for top-volume markets, slow for the rest.Keeps the feed reliable as coverage grows.Token budgets and 429 handling are described in [S5]; the public-endpoint numeric limit is not stated (F-06).
9Organize by decision, not by data. Each topic page starts with "what changed, what is liquid, what is resolving soon", then the full table.Faster to read in a live session.Layout suggestion; no external source needed.
10Push alerts to a chat channel (for example a team chat webhook) for High-ROI picks only.Catches moves while the page is closed.Idea only; no channel or webhook has been verified or connected.

Simplifications already made

  • One template for all topic pages, so navigation stays identical.
  • Markets are grouped under their event, so related outcomes sit together.
  • Every table row carries a source link, and unverified values are listed on Flagged for review.
