ROADMAP · MAKING THE DESK LIVE

Suggestions

Prioritised, concrete ways to make this site more live and more interactive. Each item states what it is, why it matters, the effort it takes, and where it already stands. Where an official Kalshi page supports the idea, it is linked.

Liveness — how the data arrives

What would make the desk more live and more usable

Push the collector cadence from 15 minutes down to 5

Shipped

What A scheduled GitHub Actions run rebuilds the snapshot every few minutes, and the browser polls assets/live.json every 30 seconds.

Why A swing of $0.10 on a 30-cent contract is a 33% move. At a 15-minute collection gap, most of those swings happen between two snapshots and are never observed.

Effort: Low Candlestick endpoint (official) ↗

Subscribe to the Kalshi WebSocket feed instead of polling

Next

What Replace the REST poll with the documented WebSocket channel at wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2 and push every tick straight into the page.

Why Ticks arrive immediately instead of up to 30 seconds late, and the chart stops depending on a GitHub Pages rebuild to show a fresh price.

Effort: Medium WebSocket quick start (official) ↗

Run the collector on a schedule that is not GitHub's

Next

What Move the same collector script to a small always-on host (or a self-hosted runner) and keep GitHub Actions as the fallback.

Why GitHub's scheduler is best-effort and can lag behind on a busy queue, which is why a snapshot can look older than the badge suggests.

Effort: Medium API environments (official) ↗

Interactivity — what the trader sees

What would make the desk more live and more usable

Let the two chats filter by topic and by direction

Shipped

What Add topic chips (gas, elections, culture, crypto, golf) and up/down toggles above each chat, and keep the filter in the URL so a view can be shared.

Why Right now the chats mix all five topics into one column, so the eye has to do the grouping that the page could do.

Effort: Low Get Markets (official) ↗

Add a spread-history strip under the price chart

Next

What Plot the implied spread alongside the price line so a wide-spread quote is visible next to the move it produced.

Why Several of the largest recorded moves sit on markets whose book is effectively empty, where the midpoint moves a long way without a fillable price.

Effort: Low Order book responses (official) ↗

One-click depth snapshot in every chat row

Shipped

What Render the resting size at the top three price levels inside the alert row, not only in the side panel, so a trader can judge whether a jump was executable.

Why The brief asks how many contracts are available at a given price; that number belongs next to the alert that raised the question.

Alerts — making the ≥ $0.10 signal trustworthy

What would make the desk more live and more usable

Show the reference price and window on every alert

Shipped

What Each chat row already prints the two prices it compared. Add the explicit reference (bar open or previous snapshot) and the elapsed time.

Why Without the reference, a reader cannot tell a real $0.10 move from a change of measurement basis.

Effort: Low Candlestick endpoint (official) ↗

Suppress alerts on markets with no executable size

Flagged for review

What Require a minimum resting size on the side that moved before an alert is published.

Why A midpoint on an empty book can jump a long way and still be untradeable, which is noise in a feed meant to be actionable.

Effort: Medium Order book responses (official) ↗

Deduplicate repeated alerts for the same market

Flagged for review

What Collapse repeats of one market inside a reference window into a single row that counts its occurrences.

Why The current buffer can show the same market many times in a row, which buries the genuinely new moves.

Effort: Low

Name the candidate cause, never assert it

Shipped

What Every ≥ $0.10 row links to the Kalshi event page — which carries Kalshi's own live news feed for that event — and to a news search built from the event title.

Why The brief asks for the links that may have caused a jump. Linking to the primary event page and a search is honest; claiming an article caused a move is not.

Effort: Low Get Events (official) ↗

Trust — keeping every number checkable

What would make the desk more live and more usable

Read the real demo account when credentials exist

Needs demo credentials

What The adapter for signed GET /portfolio, GET /orders and GET /fills already exists and is unit-tested against a local mock; it activates as soon as the demo key id and private key are set.

Why Until then the portfolio page shows a simulated book rather than the demo account the brief asks to track.

Effort: Low (code done) Requests and authentication (official) ↗

Show the snapshot age on every page

Shipped

What The top bar prints how long ago the published snapshot was taken, and the counter keeps ticking while the page is open.

Why A dashboard that refreshes every 15 minutes can be half an hour old on a quiet schedule. Saying so is cheaper than being wrong.

Effort: Low Demo environment (official) ↗

Publish the collector run log next to the data

Shipped

What Store the last run's request count, error list and coverage numbers as JSON and render them on the methodology page.

Why Coverage gaps are the difference between 'no alerts' and 'no alerts were possible'.
