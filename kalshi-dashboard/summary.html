Executive summary

Status as of 2026-11-20, updated 2026-11-21 (session arena-8a8d4294: resolution scan, live pulse, portfolio block). Live numbers are on the dashboard pages and change with each run; they are not copied into this summary.

What was built

  • Read-only live dashboard for five topics: gas prices, elections, culture, crypto and golf. Each topic page groups markets by event, shows last price, bid/ask, 24-hour volume, open interest and an order-book ladder, and offers a price chart with 1, 6, 24 and 72-hour windows.
  • Price-move alerts whenever a contract's price moves 10¢ (= $0.10) or more, in either direction, shown in two scrolling chats: all events, and the High-ROI filter. Between collector runs the same rule is measured in the visitor's browser (one anonymous batch order-book call every 45 seconds), and those rows are labelled live · browser poll.
  • Resolved outcomes — the official YES or NO result for settled markets in every mapped series, read from the documented settled listing and accumulated across runs, each row linked to both its market object and the listing that returned it.
  • Simulated (paper) trades testing three rule-based strategies, with category and strategy analysis. No real or demo orders are placed.
  • Repository review with irregularities and links (see Flagged for review).

Verified facts used

  • Public market-data endpoints need no authentication: the SDK marks them "No authorization required" [S9].
  • The demo REST host is https://external-api.demo.kalshi.co/trade-api/v2 and the demo WebSocket host is wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2, both as listed in the brief [S3].
  • The taker fee is round up of 0.07 × contracts × price × (1 − price); the maker fee uses 0.0175 and applies only where the series' maker multiplier is non-zero. Every row of the General Trading Fees Table is checked by a test [S2].
  • There is no settlement fee and no membership fee [S2].
  • Topic series on the official fee schedule: gas KXAAAGASM ("US gas price"); golf KXPGATOUR, KXPGARYDER, KXPGASOLHEIM; crypto KXBTCMAX150, KXBTCY, KXETHY; culture KXEMMY* series; elections KXELECTIRAN [S2].
  • WebSocket connections require an API key, so live streaming cannot run from a static site [S8].

Operating limits and model choices

  • Market data source: this collector is locked to Kalshi's documented demo REST hosts only. Production and custom hosts are rejected before any request; each snapshot records its exact base URL. Demo prices may not reflect real markets [S4]. A successful demo collection is required before any prior production snapshot can be treated as current (F-07).
  • High-ROI picks: a transparent rule (entry ≤ 40¢, spread ≤ 5¢, 24h volume ≥ 100), not a predictive model. Replace it with your model (F-13).

Main irregularities for review

  • Market status words differ between filters ("open", "settled") and responses ("active", "determined", "finalized") (F-01).
  • The fee rounding wording ("rounded to a centicent") does not match whole-cent table values (F-02).
  • Parts of the fee-schedule PDF text layer are scrambled (F-03).
  • The SDK's default base URL is production (F-05).
  • The settled listing documents a market-level title, not an event title, and Kalshi's own demo data carries literal markdown inside it (F-25); GET /portfolio/balance does not state a unit for its integer fields (F-26).

What the owner needs to do

  1. Create a Kalshi demo API key and add secrets KALSHI_DEMO_KEY_ID and KALSHI_DEMO_PRIVATE_KEY to enable the portfolio view (F-08).
  2. Read the Kalshi Developer Agreement before enabling any automated trading (F-17).
  3. Review the Flagged for review list and request changes.
