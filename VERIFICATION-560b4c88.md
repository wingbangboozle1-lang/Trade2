## 3. Re-derivation from the files on `main` (run these to check)

Input: `docs/data/portfolio.json`, `generated_at = 2026-11-21T06:24:59.041739+00:00`
(18 trade rows: 13 `open`, 5 `close`; 8 held positions).

```bash
python3 - <<'EOF'
import json
p = json.load(open('docs/data/portfolio.json'))
tr = p['trades']; op = [t for t in tr if t['action']=='open']; cl = [t for t in tr if t['action']=='close']
print("sum fees, open rows ", round(sum(t.get('fee') or 0 for t in op), 2))
print("sum fees, close rows", round(sum(t.get('fee') or 0 for t in cl), 2))
print("sum fees, all rows  ", round(sum(t.get('fee') or 0 for t in tr), 2))
print("published stats.all ", p['stats']['all'])
print("published account   ", p['account'])
held = p['positions']
print("cost basis held     ", round(sum(x['contracts']*x['avg_price'] for x in held), 2))
print("cash implied by log ", round(10000
      - sum(t['contracts']*t['price'] + (t.get('fee') or 0) for t in op)
      + sum(t['contracts']*t['price'] - (t.get('fee') or 0) for t in cl), 2))
EOF
```

Observed output, field by field:

| Figure | Value | Read |
| - | - | - |
| `stats.all.fees` (published) | **68.85** | equals the sum of the **close-row** fees exactly |
| sum of open-row fees | 126.02 | the entry legs, charged to cash at open, absent from that figure |
| sum of all row fees | 194.87 | what the account actually paid across the log |
| entry legs of the 5 closed round trips | **35.86** by ticker pairing, **37.12** by `(ticker, side, strategy)` pairing | so "both legs" for closed trips is 104.71 (the lab's number) or 105.97 |
| `account.cash` (published) | **10000.00** | the starting bankroll, i.e. as if nothing had been spent |
| cash implied by the same file's trade rows | **8688.09** | difference **1311.91** |
| `account.fees_paid` (published) | **0.00** | vs 194.87 charged |
| `account.realized_pnl` (published) | **0.00** | vs `stats.all.net_pnl` **413.89** in the *same file* |
| `account.equity` (published) | **11549.01** | `cash + Σ marks`; with consistent cash the same marks give 10237.10 → headline overstated by exactly 1311.91 (12.8 %) |
| `account.open_positions` | 8 | positions *were* carried across runs; only the scalars were not |

Two independent conclusions, both from the table above:

1. **The fee definition.** The published `fees` is the exit leg only. It matches
   neither both-legs total, so it is not a counting error — it is a definition, and
   the definition omitted a cost that was really charged. `tools/strategy_lab.py`
   now says which of the two it found instead of printing a bare "mismatch".
2. **The persistence bug.** `main()` writes `cash`, `fees_paid`, `realized_pnl` and
   the day fields *inside* `account`, and `Engine.__init__` read them only at top
   level — so every scheduled run restarted the money while keeping the positions and
   the ledger. The 35.86-vs-37.12 split above is the third finding: reconstructing a
   round trip by pairing is ambiguous when a ticker has more than one entry (this book
   has three such tickers: `KXRT-FUR-85`, `KXAAAGASW-26NOV23-3.6400`,
   `KXBTCMINY-27JAN01-50000.00`, each opened twice). Recording `entry_fee` on the
   close row removes the ambiguity instead of routing around it.

## 5. What is simulated, and what was not verified

* **Every figure in `STRATEGY_ANALYSIS.md`, `docs/strategies.html` and the two books
  is simulated.** No order is sent, and `docs/data/portfolio.json` says so in its own
  payload (`"mode": "simulated-paper"`, `credentials: "none — no orders are sent"`).
  The Kalshi demo environment uses mock funds and its behaviour may not reflect
  production ([demo environment](https://docs.kalshi.com/getting_started/demo_env)).
* **Not verified, cannot be verified here:** the real demo-account portfolio,
  positions, fills and any order placement. They need a Kalshi demo API key pair
  ([authenticated requests](https://docs.kalshi.com/getting_started/quick_start_authenticated_requests));
  none exists in this repository. Recorded on `review.html` as U-1/U-2 by the
  integration session and unchanged by this one.
* **Convention change, published, not hidden:** `pnl` values written before
  2026-11-21 are not restated. The payload now carries
  `stats.fee_convention.both_legs_since = "2026-11-21"` and
  `parameters.fee_legs = "entry leg + exit leg; settlement pays no fee"`, so a reader
  comparing a 2026-11-20 figure with a 2026-11-21 figure can see they are on
  different bases.
* **Timing:** `docs/data/portfolio.json` is written by the collector workflow, not by
  this session. The corrected figures appear on the next scheduled run after the
  merge; the strategy page's own age column (new) makes any lag visible instead of
  implicit.
* **Not hand-produced:** this session did not edit any file under `docs/data/` other
  than `strategy_lab.json`, which is this tool's own output.
